# EduMaterial

Projeto de portfólio voltado à prática de **Quality Assurance (QA)**, utilizando o EduMaterial como estudo de caso para análise de requisitos, planejamento de testes manuais, identificação de defeitos e documentação de resultados.

## 1. Sobre o produto

O EduMaterial é uma proposta de plataforma educacional destinada a ajudar professores a descobrir, organizar e adaptar materiais didáticos.

Uma aula pode ser composta por:
- Plano de aula;
- Slides;
- Material de apoio;
- Atividade.

A plataforma também prevê a descoberta de aulas individuais e sequências didáticas, além do download de recursos separados ou de um pacote completo de aula.

Os materiais devem permitir personalização pelo professor, que poderá adaptá-los às necessidades de sua turma.

## 2. Objetivo do projeto de QA

Aplicar práticas de garantia da qualidade de software para avaliar se os requisitos do produto podem ser verificados de maneira clara, consistente e organizada.

O projeto será desenvolvido progressivamente, começando pela análise de requisitos e pelo planejamento de testes manuais.

## 3. Escopo inicial de testes

O planejamento inicial considera os seguintes módulos:

- Catálogo e descoberta de materiais;
- Busca e filtros;
- Visualização dos detalhes de uma aula;
- Disponibilidade dos quatro componentes de uma aula;
- Download individual de recursos;
- Download do pacote completo;
- Navegação entre aulas de uma sequência didática;
- Estados de carregamento, ausência de resultados e erro.

Os cenários serão refinados conforme os requisitos forem detalhados e a aplicação se tornar disponível para execução dos testes.

## 4. Artefatos de QA

Este repositório será organizado para reunir:

- Análise de requisitos e critérios de aceitação;
- Plano de testes;
- Cenários e casos de teste;
- Dados e pré-condições de teste;
- Relatórios de defeitos;
- Evidências das execuções;
- Relatório final de testes.

## 5. Ferramentas e tecnologias

- Git e GitHub — versionamento e organização do projeto;
- Markdown — documentação;
- Ferramentas de testes manuais — a definir conforme a aplicação estiver disponível.

## 6. Status atual

**Fase:** preparação e planejamento de QA.

A documentação do produto está sendo utilizada como base para definir o escopo inicial. A aplicação ainda não está disponível para execução de testes funcionais.

Portanto, os casos de teste e os resultados serão registrados separadamente. Nenhum teste será apresentado como executado sem evidência correspondente.

## 7. Próximas etapas

1. Consolidar o escopo e os requisitos verificáveis.
2. Definir critérios de aceitação.
3. Elaborar o plano de testes.
4. Criar e priorizar os casos de teste.
5. Executar os testes quando houver uma aplicação disponível.
6. Registrar defeitos e evidências reais.
7. Produzir um relatório final com os resultados e riscos identificados.
